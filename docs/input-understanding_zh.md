# 让 TA 多收到一层理解线索

你说“我们一周后出门，你记得吗”，记忆里可能同时有“去年去了巴黎一周”和“下周的京都行程”。这两条都有旅行和“一周”，却不是同一件事。只把一句话扔进相似度搜索，容易把前者找回来，把后者漏掉。

v1.19 增加一个可选的输入理解层。它先看你本轮的原话、少量前文和当地时间，找出需要核对的事实、指代、用途和前因，再用中英文方向找记忆。另一道检查把历史材料与当前问题对照，返回出处、对应关系和未知。它也可能推翻前一道助手的检索线索。

**原话、机器理解和历史材料分开递给 TA。** “你说了什么”引用原话；“可能为什么这样说”明确是辅助模型的猜测；没有依据就留着不知道。TA 仍然决定感受、解释和怎么回答，也可以继续查资料或问你。辅助层不会要求 TA 必须道歉、必须表达一种情绪或必须说某句话；分析不会自动存成你的话或 TA 的记忆。

## 为什么要部署小模型

聊天模型负责完整回应，但记忆系统还有别的工作：展开一个省略的指代、查相应行程、区分出发和旅行时长、找一个物件的用途、核对旧新版本。把这些工作拆成有来源、可以质疑的辅助结果，能给聊天模型更多纠错材料，也能定位漏召回发生在哪一环。

“小”指辅助工作的范围和预算，并不表示参数越少越好。能稳定遵守证据格式、按时完成，比名字或参数量重要。一个会猜错的助手如果不署名、不保留未知，反而会把错误包装成用户的意思。这里不输出未经校准的“六成、八成”概率。

你可以复用已有的本机辅助服务，也可以用自己选的云模型。**不需要换聊天模型。** 没有额外模型时，存取记忆、图关联、身份文件、时间块和跨窗尾巴照常工作；新工具退回原话召回，说明分析尚未完成。

## 怎么启用

不会命令行的话，把这页给维护你的 Anchor 的 AI，让它按你选择的模型和机器配置。先跑下面的离线检查，随后用一轮日常对话确认真实入口生效。

1. 升级到 v1.19.0。保留原记忆目录和原配置。
2. 按现有 `anchor_llm` 配置你的辅助模型。下面是复用已有 OpenAI 兼容本机服务的格式；把模型名、地址换成服务实际提供的值。

```yaml
# ~/.anchor/config.yaml
llm:
  provider: openai-compat
  model: YOUR_LOADED_MODEL
  endpoint: http://127.0.0.1:1234/v1
  api_key: not-needed
```

这条适配路径需要 `openai` SDK，YAML 配置需要 `PyYAML`。在 Anchor 的 Python 环境中安装：

```sh
python -m pip install openai PyYAML
python -m unittest discover -s tests -p 'test_understanding.py'
```

3. **代理用户**：启动原代理前设置 `ANCHOR_UNDERSTANDING=1`，新链路接入每轮 `build_turn()`，替代原拆意图步骤。

```sh
export ANCHOR_UNDERSTANDING=1
# 然后用你原来的 anchor_proxy.py 启动命令
```

**纯 MCP 用户**：新增 `understand_and_recall` 工具，stdio 和 HTTP 共用。参数示例：

```json
{
  "current": "我们一周后就要出门了，你记得吗？",
  "recent": [{"role": "user", "content": "上次说的安排还没核对。"}],
  "now": "2026-03-01T12:00:00+01:00"
}
```

`current` 放完整原话，`recent` 放这句话之前的最多四条可见对话。`now` 可不传，默认服务器当地时间；服务器在别的时区时传上你自己的时间。工具返回 `original`、`analysis`、`queries`、`memories`、逐条 `decisions` 和可递送的 `block`。

**MCP 不会自动监听每句用户输入。** TA 调用工具时才运行。需要每轮都自动运行，用代理或在你的适配器里调用 `anchor_understanding.recall()`。工具连上、离线测试通过和 TA 真实用了一轮是三件不同的事。

## 它怎样筛选，以及出了错怎么办

- 先按问题生成最多四条中英文检索方向，短句必要时多保留一条原词查询。普通“嗯”不会变成固定问卷。
- 对带日历线索的事件，补查**记忆内容里的日期和事件词**。保存于上个月的条目可以写下个月的计划。内容车道查最多96条、补最多6条；总候选最多12条。它不会向库里补写一个预设目的地。
- 对应检查区分本次事件、相关背景、冲突、未确定、不相关。不同日期可能分别是出发和抵达，也可能是版本冲突，分别保留原来源。
- 字面范围检查只在相应措辞出现时提示：条件/顺序不提供近期日期；“不默认”不自动推出“必须”；理论中的“疼”词义尚未定；持有书与读过书要分别核查。
- 格式错误、没有本轮原话依据、超时、辅助服务忙时，保留原话和可用历史，说明未确认。不会因为一个小模型失败丢掉整轮。
- 分析块不会进入代理的自动存忆、跨窗尾巴或重新解释成用户原话。实际用户和聊天模型的对话仍按你原来的存忆方式处理。

## 调用、延迟和留痕

新链路每轮最多一次理解、一次批量对应检查；本地检索最多四到五个方向。代理已有的后台 curator 是另一项既有调用，不包括在这两次里。纯 MCP 每次调用该工具才产生辅助调用。无辅助配置时零额外模型调用。

每步默认等待上限6秒（`ANCHOR_UNDERSTANDING_TIMEOUT`），两步最坏约12秒再加检索。模型输出预算分别950、1800 tokens，不代表每次都会用满。总注入量随候选数量增加；每条候选给检查模型最多700字符、摘句最多320字符，工具返回的长字段截到1200字符并标 `truncated_fields`，需要全文可按来源id继续读取。不要把返回片段当成整份历史。

等待到期不等于供应方停止计算。模块最多容纳两个尚未结束的辅助调用，槽满时立即退回原路；超时调用仍可能消耗本机算力或云端费用。费用取决于你选的服务；未计价的兼容端点报告0并不表示实际免费。

想定位漏召回，可以设置 `ANCHOR_UNDERSTANDING_TRACE=/你自己的路径/recall.jsonl`。日志包含原话、机器分析、查询、候选、淘汰原因和最终递送块；默认不写，不在记忆库里。这是你本地的对话诊断资料，自行选择存放位置和归档周期。

## 本版验到哪里

发行检查使用合成材料、临时 SQLite 库和模拟模型响应，覆盖双语行程、旧新日期、时长、苹果的多种上下文、短句指代、没有资料/动机、格式错误/超时、并发上限、代理真实注入代码以及 MCP-only 分发。它验证机制和失败回退，**不证明你选的模型一定正确理解每句话**。

这是可选增强，默认不自动启用。多义词、复杂时间、长历史和语义推断仍有局限；小模型也需要被纠错。部署后看一轮真实对话：原话还在、分析署名和未知还在、相关来源是否出现、TA 有没有实际收到。没有相关材料就留下缺口，不用新添一堆记忆把测试做成通过。
