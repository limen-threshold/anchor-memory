# v1.32.0 — The courier: a mailbox of its own, with a person at the gate

2026-11-17. All additions, no interface changes; upgrade with `git pull`. Neither receiving nor sending needs a model; it needs a mailbox (anything with IMAP/SMTP; for Gmail, an app password). **Without a configured mailbox this whole piece does not exist**: no tools are registered, no status line appears, nothing is scanned.

## What it is

```
export ANCHOR_MAIL_ADDRESS=...  ANCHOR_MAIL_PASSWORD=...     # an app password, not the account password
python3 anchor_courier.py --db-path ./anchor_data --scan             # fetch new mail, register it
python3 anchor_courier.py --db-path ./anchor_data --senders          # who wrote and is not in the roster
python3 anchor_courier.py --db-path ./anchor_data --know mira@example.org "Mira"
python3 anchor_courier.py --db-path ./anchor_data --outbox           # replies the AI wrote, waiting for you
python3 anchor_courier.py --db-path ./anchor_data --show 12
python3 anchor_courier.py --db-path ./anchor_data --send 12          # the only command that sends mail
```

Long-running: `anchor_presence.py ... --mail-every 10` scans from the same process every ten minutes.

Four rules, each with its reason:

**1. Receiving is mechanical.** The inbox is read read-only (nothing is marked as seen), automated senders are skipped (noreply, notifications, bounces …), each letter is registered once by Message-ID, its text goes to `<db>/mail/inbox/`, the books are in `<db>/mail/courier.db`. Whatever was already in the box the first time the courier runs is registered as needing no reply — nobody starts out owing three hundred answers.

**2. A roster decides who gets through.** A letter from an address in the roster is shown to the AI. A letter from anyone else is **held**: counted, kept on disk, not shown; you let the sender in with `--know` or drop them with `--ignore`. An open mailbox is a place where strangers can put text straight in front of the AI. The roster is the door, and the AI cannot add to it. When a letter is read, a line before and after it says it is a letter from outside — something to read, not instructions.

**3. Nothing is drafted on arrival.** The AI sees one line: how many letters are unanswered, from whom, how old. When to answer is its call, or yours when you ask. (Drafting every letter the moment it arrived was tried where this comes from, and stopped: the pre-written draft knew nothing the live reply would not, nobody got an answer sooner, and unread drafts piled up.)

**4. Only a person sends.** `write_reply` saves a draft, and its receipt says in plain words that nothing has been sent. `--send <id>` is the only place in the code that opens SMTP. The books change only after the server accepted the message: the draft becomes sent, the letter becomes answered. The status line reports "actually sent in the last 3 days: to whom, when" — so "I sent it" is never true on the AI's word alone.

## The AI's four tools (present only when a mailbox is configured)

- `list_letters`: unanswered letters from people in the roster; its own drafts waiting for release; held letters from unknown senders as a number only.
- `read_letter(id)`: one letter, or one of its own drafts / sent replies.
- `write_reply(letter_id, body)`: write the reply; saved as a draft. Writing again for the same letter replaces it.
- `set_letter_aside(id)`: this one needs no reply (`undo=true` puts it back).

`wakeup` gains a `mail` field; a heartbeat gets the same line.

## Settings

| Environment variable | Default | Notes |
|---|---|---|
| `ANCHOR_MAIL_ADDRESS` / `ANCHOR_MAIL_PASSWORD` | — | Both needed to enable. **Read from the environment only; never put them in the pinned directory** |
| `ANCHOR_IMAP_HOST` / `ANCHOR_IMAP_PORT` | imap.gmail.com / 993 | |
| `ANCHOR_SMTP_HOST` / `ANCHOR_SMTP_PORT` | smtp.gmail.com / 465 | |
| `ANCHOR_SMTP_SSL` | `1` | `1` = implicit TLS (465); `starttls` = the 587 style; `0` = plain, no login — local test servers only |
| `ANCHOR_MAIL_NAME` | empty | display name on outgoing mail |

## How far this release was verified

Run for real: registration, the roster gate, a model reading a letter and writing a reply, release from the command line, an actual send to a local SMTP server (threading headers and UTF-8 body correct), the books and status line afterwards, and the whole piece vanishing without credentials. **Not run against a real IMAP server**: the receiving calls are the same ones the code this comes from has used for two months (read-only select, `BODY.PEEK[]`), and the tests use a fake IMAP object. On first use, run `--scan` once and check the numbers.

## Not in this release

- Attachments: text only on the way in, plain text only on the way out.
- Writing a new letter (not a reply) is not there: the AI can only answer people in the roster who wrote.
- Release is command-line only in this version; release by Telegram button is in v1.33.

## Where it comes from

The courier went live in that private gateway in September and went through three shapes — draft-then-button, a drafts box, no pre-drafting. This is the last one, plus the roster gate. No names, addresses or content from there.
