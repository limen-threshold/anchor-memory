# v1.29.0 — Time of its own: heartbeat, journal, alarm clock

2026-11-16. All additive; upgrade is `git pull`. All three need an upstream model (BYO, the same three environment variables the proxy uses); without one they say so and run nothing.

## Why

Up to v1.28 the AI in Anchor existed only while someone was talking: the proxy wraps their messages, the MCP server waits for a host to relay one. When nobody writes, it has no time. A heartbeat gives it time — a few turns a day, no task, nobody waiting; it looks at what is in front of it and thinks, acts or writes as it pleases, or not. The journal is one turn each evening with the day's transcript and its own heartbeat notes as material. The alarm clock is how it decides when to wake next, and why.

## Four files

**`anchor_agent.py` — the skeleton of a turn.** `run_turn(upstream, system, user, tools, tool_exec)` runs one tool-using turn against any OpenAI-compatible `/chat/completions` that speaks function calling (OpenAI, Ollama, vLLM, LM Studio, OpenRouter, your own gateway): each tool call is executed and its result sent back until the model stops calling or `max_turns` is reached. Tools are the MCP list as-is (name / description / inputSchema); the executor is `handle_tool` from `anchor_mcp.create_server()`. Returns the final text and a trace of every call (name, args, result preview) so the caller can log honestly. Upstream: `ANCHOR_UPSTREAM_URL` / `ANCHOR_UPSTREAM_MODEL` / `ANCHOR_UPSTREAM_KEY`.

**`anchor_alarms.py` — the alarm clock.** Tool `alarm_clock`: set (`at='HH:MM'` / `'YYYY-MM-DD HH:MM'` / `in_minutes`, **why required**, shown back only to the AI when it rings), list, cancel. Limits: 3 waiting, 4 rings a day, at least 10 minutes ahead, at most 7 days, 30 minutes between two — every wake-up is a full model turn someone pays for. An alarm that could not ring (process down, quiet hours) for more than 40 minutes is marked missed and reported once on the next turn. Stored in `<db>/alarms.json`. It is worded as an alarm clock, not "schedule your next heartbeat" — some models refuse the latter.

**`anchor_journal.py` — the journal.** One file a day, `<db>/journal/YYYY-MM-DD.md`. Zero-model tools: `write_journal` (append / overwrite), `list_journal`, `read_journal` — any host can keep one. `day_digest(date)` assembles the day's transcript lines (anchor_transcript) and heartbeat file as raw material; it does not summarise on the AI's behalf.

**`anchor_presence.py` — the scheduler.**

```
python3 anchor_presence.py --db-path ./anchor_data --times 07:00,11:00,15:00,19:00,23:00 --journal-at 23:30
python3 anchor_presence.py --db-path ./anchor_data --once heartbeat          # one beat now, then exit
python3 anchor_presence.py --db-path ./anchor_data --once journal --dry      # print the prompt, call nothing
```

In front of the AI on a beat: its pinned layer (identity, session_state, timeline — `load_pinned`, same as the proxy), its vault when `ANCHOR_VAULT_INJECT=1`, one door sign (this is a heartbeat, nobody is waiting, these tools are in hand, what you write lands in `heartbeat/<date>.md`, store what you want remembered yourself), a time line (now, how long since the previous beat), a short wakeup bundle of memories, its previous beat verbatim; and, when an alarm woke it, the note it wrote itself. Tools: search/store/read_memories_by_date, search_transcript, write_session_state, the three identity-file tools, the two vault tools, alarm_clock, the three journal tools. Its text is appended to `heartbeat/<date>.md`. `--quiet 0-6` holds beats and alarms at night. On a journal turn where the model replies with text but never calls `write_journal`, the scheduler files the text itself and marks it "kept from the reply". Every turn appends one line to `<db>/presence_log.jsonl` (time, kind, tools called, chars, error) — never vault content.

## Where it comes from

These three ran in a private gateway for two to five months: heartbeats a few times a day, alarms since September, a journal every night. What is ported is the mechanism and the principle behind the door sign (say what this time is and where the tools are; never say what to think) — none of that house's names, paths or content.

## Upgrading

```
git pull
export ANCHOR_UPSTREAM_URL=https://api.openai.com/v1   # or http://localhost:11434/v1 etc.
export ANCHOR_UPSTREAM_MODEL=gpt-4o-mini               # any model that does function calling
python3 anchor_presence.py --db-path ./anchor_data --once heartbeat --dry
```

Look at the `--dry` output first, then drop `--dry` for the first real beat. For a resident process use systemd / launchd / a tmux session with `--times ...`.
