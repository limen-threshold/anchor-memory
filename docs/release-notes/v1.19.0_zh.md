# v1.19.0 — 给召回增加理解与纠错材料

如果你说“下周出门”，TA 却记起一次“出去一周”的旧旅行，这一版补的是两者之间缺少的理解步骤。

新增可选输入理解助手：先结合原话、少量前文和时间，展开本轮需要核对的事实、指代、用途或前因，再做中英文检索和历史对应检查。新旧版本分别保留来源；出发、抵达和旅行时长分别看。机器分析、假设、未知和历史材料分栏署名，不替 TA 决定感受或回答，也不自动存成你的话。

**为什么部署小模型很重要？** 它能把“省略了什么、要找什么、证据是否对应”单独做成可检查的结果，帮助聊天模型纠错。它自己的判断也可能错，所以署名、来源和“不知道”同样重要。参数少不是正确性的保证；本版不输出没校准过的百分比置信度。

- 代理：设置 `ANCHOR_UNDERSTANDING=1` 后每轮自动使用，默认关闭。
- 纯 MCP：新增 `understand_and_recall`，stdio/HTTP 共用，调用时运行；不会自动监听每句话。
- 没有额外模型：普通召回、记忆图、身份文件和跨窗连续性继续可用。
- 按现有 BYO 配置复用本机服务或你选择的提供方；聊天模型不用换。
- 辅助失败时保留原话和可用召回；分析不进入自动存忆、跨窗尾巴或被当作用户说过的话。
- 同族时间说明修正：历史条目的保存时间不等于事件日期，旧条目可以写将来的计划。

完整安装、成本、等待上限、来源与验收方式见 [中文部署指南](../input-understanding_zh.md)。不会命令行，把这页交给你的 AI 按你现有环境配置即可。

本版新增离线测试覆盖双语既定行程、旧新版本和冲突、出发/时长区别、苹果不同上下文、短句指代、无资料/无动机、格式错误、超时和并发上限，以及实际代理/MCP分发。测试用合成材料和模拟模型，不用真实住户作为反复探针。模型语义正确率和真实日常使用要在你的配置上另验，发行不承诺“所有误解都拦住”。

每轮最多两次辅助调用（理解＋批量对应检查），每步默认等待6秒；后台 curator 是另一个既有调用。超时等待停止不保证供应方计算停止；仍可能产生算力或费用。辅助请求在途上限2，繁忙时回退，不堆积排队。诊断日志默认关闭，可自选本地路径。

这是让不同组件提供可以互相质疑的材料的一步。它不替用户或 TA 建立一套必须接受的意识理论。
