# v1.25.0 — 一次外部审读，修掉四处静默失效

2026-11-14。接口不动，升级就是 `git pull` + `pip install -r requirements.txt`。

## 怎么来的

请了一个没看过这个仓库的审读者（一个干净上下文的 Claude，只读克隆、不跑模型、不碰库）把代码从头读一遍。它找出来的东西有一个共同点：**都不报错**。功能看起来在跑，结果悄悄是错的。这一版把它列的前几条修掉，其余的（见文末「没改的」）留到下一版。

## 修了什么

### 1. 两套时钟混用：`dream_pass(verify=True)` 对 UTC+8 用户整体偏八小时
记忆的时间戳是 UTC（`anchor_db` 用 `utcnow()`），原话转录和时间线是本地时间（`datetime.now()`）。做梦时拿记忆的 UTC 戳 ±3 小时去切本地时间的原话，在 UTC+8 下窗口整体偏了八小时——要么切不到任何对话（`no_transcript`），要么拿错时段的话去「核对」。

修法：`anchor_guards.py` 新增 `parse_ts_naive` / `utc_to_local_naive`，`_transcript_around` 先把记忆戳换到本地再开窗；`verify_recent` 的「最近 7 天」用 `utcnow()` 跟库比。存储格式不变（仍是 naive UTC）。

### 2. 带时区的时间戳让 `search()` 整体抛错
`_recency_boost` 里 `fromisoformat` 在 try 里，减法在 try 外。导入数据里一条 `2026-11-14T18:00:00+08:00` 进了候选，整次搜索就返回 `{"error": "can't subtract offset-naive and offset-aware datetimes"}`。

修法：所有时间戳经 `parse_ts_naive` 统一成 naive UTC 再减；`store(timestamp=…)` 存之前也先换算，`Z` 和 `+08:00` 都认。

### 3. 库代码 `print` 打进 stdio 的 JSON-RPC 通道
stdio 模式下 MCP 的协议走 stdout，而 `anchor_memory` / `anchor_db` / `concept_link` 的诊断 `print` 也走 stdout——普通 `store_memory` 触发近重复合并就会给客户端吐一行非 JSON。另外主循环读到一行坏 JSON 直接抛异常，整个服务器退出。

修法：库代码的 `print` 全部改到 stderr；坏行回 JSON-RPC `-32700` 解析错误，继续服务。CLI 脚本自己的输出不变。

### 4. 关键词车道先截断再打分
`keyword_search` 是 `WHERE … LIKE … LIMIT 300`，没有排序，按 rowid 取前 300 再在 Python 里按命中词数打分。库里只要有 300 行以上含某个常见词，同时含全部查询词的那一行就可能根本不在池里（审读者用 350 条「garden」+1 条「garden hose」复现了）。库越大、词越常见，越容易全军覆没。

修法：SQL 里按命中词数 `ORDER BY … DESC` 再 `LIMIT`。不按时间排（v1.10 的教训：车道不预判新旧）。

### 5. `search_multi` 的同日上限还在用 v1.20 的键
v1.21 把 `search()` 里的上限改成按（日，会话 entity）计，但多意图合并后的复检还是只按日计——而代理每轮真实走的就是 `search_multi`，所以生产路径没吃到 v1.21 的修。现在两处同一个键，关键词车道的命中也照 `search()` 的规矩另记一本账。

### 6. README 推荐的 `gpt-5-nano` 不认代码发的参数
`anchor_llm` 对 OpenAI 一律发 `max_tokens` + `temperature=0.5`；gpt-5 系和 o 系要求 `max_completion_tokens`、不接受非默认温度。按 README 配好 `openai/gpt-5-nano`，策展员和意图切分每次都 400，再被调用方的 `except` 吞掉——用户只会看到「配了模型但什么都没存」。

修法：`openai_token_kwargs(model, …)` 按模型族发参数（推理模型给 `max_completion_tokens` 并留出隐藏推理的余量）。

### 7. 相似度过线但名字 / 数字不同的，当更新不当重复
近重复闸（cos ≥ 0.93）以前只放行含「勘误 / 更正 / 作废 / correction」的句子。「猫叫 Scott」→「猫叫 Scout」会被吞掉，还给**旧的错误**那条 +1 引用。现在两段话若任一方有对方没有的拉丁词或数字，两条都留着（梦程序的 fact-check 看得到这一对）；纯措辞差异照旧合并。中文名字不在这条规则里（没有通用的中文实体表），仍走相似度闸。

### 8. 梦程序不再给随机记忆加引用
`dream_pass` 的自动发现每晚随机抽 5 条、各搜 3 条，那次 `search()` 没传 `no_cite=True`，15 条随机记忆每晚 `usage_count+1`。几个月下来随机记忆被推到前排。现在传了。

### 9. 安装会撞到的
- `requirements.txt` 补 `pyyaml`（`anchor_llm` 读 `config.yaml` 必需；以前没装时静默当空配置，表现成「No LLM configured」）和 `httpx`（代理必需）。现在 `config.yaml` 存在而 pyyaml 不在会明确报错，不再装作没配。
- README 写明首次启动要从 huggingface.co 下载约 470MB 的 embedding 模型、怎么预热、怎么配 `HF_ENDPOINT` 镜像；写明模型只嵌前 128 token。
- 身份文件、时间线、概念缓存等所有文本文件读写补 `encoding="utf-8"`（Windows 默认 GBK，写带 emoji 的 `我是谁.md` 会报编码错）。
- SQLite 开 WAL + 5 秒 busy_timeout（代理和 MCP 同时开着时不再「database is locked」），`memories` 表补 `timestamp` / `(tier, timestamp)` / `pinned` 三个索引。
- `recent_timeline.md` 的追加改成加锁 + 原子替换，代理后台线程和 MCP 同时写不再丢行。
- README 的边衰减说明改成跟代码一致（所有边 ×0.9，≥1.5 的再 ×0.95）；发布说明索引补上 v1.20–v1.25。

## 没改的

- 存储时间基准仍是 naive UTC。改成带时区会动到每一条已存的行，收益不抵风险；边界处统一换算就够。
- 近重复闸的中文名字差异仍不单独判。要的话在 `near_dup_bypass_words` 里加词。
- 审读还列了代理里的几处（最后一条用户消息里的图片被丢、LLM 调用在事件循环线程里同步跑、坏 JSON 整轮丢弃无死信）——留到下一版。

## 升级

```
git pull
pip install -r requirements.txt
```

第一次用新版打开旧库会自动建三个索引、把 journal 切到 WAL（多出 `memories.db-wal` / `-shm` 两个文件，备份时一起拷，或先 `sqlite3 memories.db "PRAGMA wal_checkpoint(TRUNCATE)"`）。其余零迁移。
