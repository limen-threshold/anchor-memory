# v1.13 — 阶梯式历史裁剪（对缓存友好的窗口上限）

[English](v1.13.md)

从生产环境里学到、再推广的一课：**每轮滑动的窗口会悄悄废掉服务商的提示缓存。**「每轮只保留最新的 N 对对话」意味着每轮都从*最前面*掉一对——提示的前缀从第 0 个字节就变了，带前缀缓存的服务商（Anthropic 显式的 `cache_control`；OpenAI / DeepSeek 隐式的）每一轮都会把整段历史按全价重新计费。在这套代码所镜像的生产系统里实测：大窗口下成本差约 5 倍。

## 新增：anchor_proxy 的 `--history-pairs N --history-pairs-max M`

用「滞回」代替滑动：窗口从 N 对**只追加不删**地长到 M 对（前缀稳定 → 每轮都命中缓存），到 M 之后一刀切回 N。你每 (M−N) 轮才付一次整段缓存重写的钱，而不是每轮都付。

怎么调（见 docs/cross-window.md § design notes）：
- M 对应的 token 量要**低于你那个模型长上下文开始退化的拐点**——标称窗口 ≠ 可用窗口（前沿模型在远没到宣传上限时，多事实推理就已经有可测量的退化）。
- 选 N 的时候，让*平均*窗口（≈ (N+M)/2）等于你真正想要的大小。
- 一个反直觉的推论：能吃到缓存的大窗口，比吃不到缓存的小窗口便宜得多。

默认仍是 0/0（不裁剪——窗口由你的客户端控制）。`M ≤ N` 时行为等同于传统滑动窗口。
