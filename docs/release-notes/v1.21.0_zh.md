# v1.21.0 — 第一次跑公开基准，抓出两处检索层的病，修掉

[English release notes](v1.21.0.md)

v1.20 一起放出的还有 LongMemEval-S 的检索跑分（`benchmarks/longmemeval/`，500 题、零模型、按会话算召回率）。跑出来的数不好看：Anchor 自带的那个 embedder 单独跑，86.6% 的题能把全部证据会话捞进前 5；Anchor 搭在它上面的那层检索逻辑，只有 70.2%。消融把差距全部定位到两处，加分项（引用/情绪/新近）无辜。这版修这两处，接口一个没动。

## 1. 同日上限改按「日 + 会话」计，不再只按日

`_allocate_slots` 里同一天最多出 2 条，是因为一个人的记忆库里，同一个下午写的五条多半是同一件事，不限就会把第二个话题挤出去。但库里一天有好几个不相干的会话时（LongMemEval 一天约 5 个会话，多会话题和时序题要的证据常常同一天），这条假设就反过来伤人。

- 存的时候带了 `entity=`（会话号、笔友对、任何会话键）的记忆，上限按 `日|entity` 计：同一天不相干的会话不再共用一个名额。
- 没带 entity 的记忆，行为和以前一模一样。
- 向量路的候选从向量库元数据带出 entity；关键词路命中的，批量补一次。

## 2. 关键词车道按命中词数给分、不认虚词

以前 `_keyword_fallback` 给所有 LIKE 命中任一词的行统一 0.6 分，并且只取数据库吐出的前 n 行。英文问句里大半是虚词（what / did / with），一句话能命中整个库，于是这条车道返回的是**按入库顺序的前几行**、每行 0.6——比所有余弦距离大于 0.6 的向量命中都靠前。

- `AnchorDB._tokenize_query` 去掉虚词（中英文都有）。表故意很短：只放几乎每句话都出现、因此能命中几乎每条记忆的词。按实例覆盖：`db.keyword_stopwords = {...}`。
- 车道先捞一个宽池（`max(8·n, 300)`），只留含至少两个查询词（或唯一那个词）的行，按 `0.65 − 0.45 · 命中数/总数` 给分：整句字面命中 0.20 压过好的向量命中，孤零零一个弱命中（约 0.5 以上）压不过。
- `search(..., debug=True)` 时每条关键词命中带 `_debug_keyword_matches`。

## 跑分（同 v1.20 口径；见 `benchmarks/longmemeval/README.md`）

按会话算的召回率，LongMemEval-S cleaned，500 题，无重排、无问答。

| 车道 | 前 5 全中（v1.20） | 前 5 全中（v1.21） | 前 10 全中（v1.20） | 前 10 全中（v1.21） |
|---|---|---|---|---|
| `anchor_default` | 70.2 | **80.6** | 75.8 | **91.4** |
| `anchor_plain`（关上限） | 79.2 | 80.6 | 83.0 | 91.4 |
| `vector_only`（天花板） | 86.6 | 86.6 | 94.8 | 94.8 |

分题型（默认车道，前 5 全中）：多会话 58.6 → 66.9，时序 38.3 → 69.2，知识更新 92.3 → 94.9，单会话用户 94.3 → 95.7。有一类反向：单会话偏好 93.3 → 83.3（30 题，差 3 题）——以前那条固定分的关键词洪水恰好把这几题带出来了；v1.22 前该看一眼。

这版 `anchor_default` 和 `anchor_plain` 在这份数据上完全一样：带了 entity，上限就再也没咬到人。离 embedder 天花板还差的 6 个点，是命中两个词的关键词行压过了较弱的向量命中——打分的取舍，不是洪水。

## 升级

直接换文件。库不用迁移。以前靠单个常见词从关键词路把一条记忆带出来的，现在要两个实词或一个稀有词——那正是被灌满的那条路。
