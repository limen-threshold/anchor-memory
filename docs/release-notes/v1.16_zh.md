# v1.16 — MCP 服务的 HTTP 传输

[English](v1.16.md)

**一句话：** `anchor_mcp.py --http` 通过 HTTP 提供同一套工具，于是那些只能连一个网址的客户端（claude.ai 自定义连接器、ChatGPT、任何远程 MCP 宿主）也能用 Anchor 了。stdio 仍是默认方式，没有任何变化。

## 为什么

Anchor 的设计准则是*任何人、任何平台、任何 AI*。四扇门里有三扇早就做到了——Python 库、给会拉起子进程的宿主用的 stdio MCP、给任何能改 base URL 的前端用的 OpenAI 兼容代理。第四类客户端，也就是托管的聊天应用，这三样都没有：没有 base URL 可改，没有本地进程，碰不到文件。它们唯一的门是「某个网址上的远程 MCP 服务」，而 Anchor 只会说 stdio。README 甚至声称普通 MCP「在 claude.ai 等平台上」能用——其实不能，因为缺了传输层。这一版把它补上，也把那句话改对。

## 做了什么

- `anchor_mcp.py --http [--host 127.0.0.1] [--port 3333] [--token SECRET]`
  - **Streamable HTTP**（MCP 2025-03-26 / 2025-06-18），地址 `POST /mcp`：JSON-RPC 进、JSON-RPC 出；接受批量；通知回 `202`；`initialize` 时发 `Mcp-Session-Id`；`GET /mcp` 回 `405`（没有服务端推送流），`DELETE /mcp` 结束会话。
  - **旧式 HTTP+SSE**（MCP 2024-11-05），`GET /sse` + `POST /messages?sessionId=…`，给还只会说这个的宿主用。
  - 可选的 bearer token（`--token` 或环境变量 `ANCHOR_HTTP_TOKEN`）。不设的话，网址本身就是秘密——躲在随机隧道网址后面没问题，放在普通公网主机上不行。
  - 工具调用是串行的（一把锁），和 stdio 一样严格：一个 SQLite、一个 Chroma、一个嵌入模型。
- `handle_message()` 现在是两种传输共用的唯一 JSON-RPC 分发器，两边不会走样。
- `initialize` 在客户端的 `protocolVersion` 是我们认识的版本（`2024-11-05`、`2025-03-26`、`2025-06-18`）时原样回传；否则照旧回 `2024-11-05`。
- 需要 `fastapi` + `uvicorn`——代理本来就用的那两个；stdio 模式仍然两个都不 import。

## 自己验一下

`python3 smoke_http.py` 会在一个空闲端口上、对着一个一次性数据库起服务，跑 12 项检查：initialize / 通知 / tools/list / 存+搜来回 / 批量 / 错 token → 401 / 未知方法 → `-32601` / `GET /mcp` → 405 / SSE 端点事件 / SSE 从流里回答 / 与 stdio 对齐（工具列表完全一致）。已有的 `tests/smoke_v114.py` 和 `tests/smoke_invite.py` 不变、全绿。

## 怎么给它一个网址

写在 README 的 *claude.ai / hosted clients* 一节：自己的机器加一条隧道（`cloudflared tunnel --protocol http2 --url http://127.0.0.1:3333`，或 ngrok），或者一台常开的小主机，用 `--host 0.0.0.0 --port $PORT`、数据库放在持久卷上。怎么选只看一个问题：你的机器会不会一直开着。

## 这一版没有的

- 没有 OAuth。claude.ai 的连接器可以不带认证添加；bearer token 是给其他所有场合用的。
- `/mcp` 上没有服务端 → 客户端的推送流（没有订阅、没有进度通知）——Anchor 目前没有什么要推的。
