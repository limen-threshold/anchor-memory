# v1.22.0 — 沉下去不等于删掉；老记忆保底不许踢字面命中

[English](v1.22.0.md)

两处小改，改的都是「`search()` 和 `dream_pass()` 允许扔掉什么」。接口不变；`AnchorMemory` 上多两个开关，老行为一行赋值就回。

## 1. short 层记忆默认不再删除

v1.21 以前，`short` 层超过 14 天的记忆会被 `decay_short()`（`dream_pass()` 也会调它）删掉——v1.18 起删前先归档到 `deleted_memories.jsonl`，但两个库里都没了。v1.22 起：

- `decay_short()` 不叫不动。`AnchorMemory.short_delete` 默认 `False`；`decay_short(days, delete=True)` 或 `short_delete = True` 回到原来的 14 天删除（先归档、两库同删）。
- 这些行别的什么都不变：不降权、不设下限、不加新的分项。它们和所有记忆一样靠新近加分慢慢归零而沉下去，一直可检索。
- `AnchorDB.decay_short()`（只动 SQLite 的那个）没动，它本来就不是推荐入口。

为什么：在这个库的上游部署里，删除这一步是梦程序里唯一丢数据的一步，也是唯一错了几周后才发现的一步（九月一次时间戳修正让二十条碎片一夜之间过了 14 天线）。「遗忘=删除」没有换来「遗忘=下沉」换不来的东西，却换掉了回头看的可能。层名保留，老库和老调用方照常工作。

## 2. 老记忆保底不许踢关键词车道的命中

`_allocate_slots` 保证最终前 N 里至少有 `older_reserve` 条超过 `older_days` 的老记忆；前 N 被新记忆占满时，它把分数最差的新行换成最好的老行。上游 2026-10-22 回放抓到这个替换踢掉了两条**字面**命中——关键词车道按查询原词找到的行，分 0.10——换进来两条分 0.42、什么都答不了的旧向量命中。

- `_debug_source == "keyword"` 的行永远不当牺牲品。`AnchorMemory.protect_literal = False` 回 v1.14～v1.21 的行为。
- 两条新行分数并列时踢后面那条（名次低的）；以前 `max()` 取的是前面那条。
- 上游那刀还有一条「老行分数没好出一截（那边 0.25）就不换」。这条**没港**：那个阈值是按那套部署的分数分布标的，换 embedder 就不成立。

## 跑分说明

LongMemEval-S（`benchmarks/longmemeval/`）把每条材料都按 2023 年的原时间戳入库，按保底的定义全部是「老」行，老记忆保底在那上面从不触发——这两处改动动不了分数。v1.22 抽 40 题做了一次对照，逐题各车道结果与 v1.21 完全一致（`benchmarks/longmemeval/runs_v121/` 进仓的是 v1.21 的汇总；逐题文件按该目录的 `.gitignore` 只留本地）。保底闸由 `tests/smoke_v122.py` 覆盖；删除开关由 `tests/smoke_v122.py` 和改成显式开启的 `tests/smoke_v118.py` 覆盖。

## 升级

不用迁移。以前靠 `dream_pass()` 清 `short` 行的，构造后加一行 `mem.short_delete = True`。
