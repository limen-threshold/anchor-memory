# v1.17.0 — 通过 MCP 读写身份文件

[English](v1.17.0.md)

起因是一位只用 Chat 的安装者（2026-09-18）：TA 能把 Anchor 接到 claude.ai 上，却没有任何办法维护 README 里说的那份*身份文件*——也就是 AI 的自我描述：`write_session_state` 只能写 `session_state.md`，而托管客户端碰不到常驻文件夹。

## 新工具

- `list_identity_files()` —— 列出常驻目录里所有 `wakeup()` 会装载的 `.md`，带大小、修改时间、类型，以及 `_order.txt` 清单里有没有列它。
- `read_identity_file(name)` —— 读出某个常驻文件的当前全文。
- `write_identity_file(name, content, mode="overwrite"|"append")` —— 新建、覆盖或追加。覆盖之前会先把旧版本归档到 `identity_archive/<文件名>_<时间戳>.md`；追加永远不会丢东西。只接受纯 `.md` 文件名（不带路径、不以点开头）；`session_state.md`、`recent_timeline.md`、`last_session.md`、`_order.txt` 会被拒绝（这几个由 Anchor 自己维护）。内容上限 30 000 字符。如果存在 `_order.txt` 而里面没列这个文件，返回结果会带一条警告：清单更新之前，wakeup 不会装载它。

## 为什么要有身份文件（引出这一版的那个问题）

一条记忆是一块碎片，得在搜索里赢了——或者被置顶——才会回来。身份文件是一整段第一人称的文字，每个窗口都原样、不经排序地回来。在托管客户端上，两者都经由同一个 `wakeup()` 的结果送到，所以区别在于它们*是什么*，不在于它们怎么送达。

写身份文件的要点：写「我是谁」，不是「用户是谁」；一行一件事，带日期，用第一人称。文件名随你（`identity.md`、`我是谁.md` 都行）。

## 这一版还带了什么（文档，来自同一位安装者的反馈）

- README：依赖装在虚拟环境里的时候，`python3` 指的是你虚拟环境里的那个解释器（`.venv/bin/python …`，`claude mcp add` 时也一样）。
- `requirements.txt`：把 `fastapi` / `uvicorn` 列为 `--http` 的附加依赖（只装了 chromadb 自带的 uvicorn 时，`--http` 会报 `No module named fastapi`）。
- README 连接器那一步：claude.ai 的 *Request headers* 栏里，**`Bearer` 后面的那个空格**可能会被吞掉；隧道的请求日志里看得到真相。
- `docs/cross-window.md`：只有 MCP 的配置下怎么用身份文件。
