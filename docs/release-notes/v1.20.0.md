# v1.20.0 — raw transcripts, injected-layer size, evidence check in the dream pass

[中文发布说明](v1.20.0_zh.md)

Three additions, prompted by Anthropic's write-up on the components of agent memory (transcripts → notes → organised representations → injected context, plus offline "dreaming" that checks notes against transcripts). None of them changes an existing API; the zero-extra-model floor holds for the first two.

## 1. Transcripts are a first-class layer (`anchor_transcript.py`)

Memories are what the AI (or its curator) chose to write down. Transcripts are what was actually said. Keeping both means you can go back to the words when a memory looks wrong.

- **Storage**: `<db_path>/transcripts/YYYY-MM-DD.jsonl`, one JSON line per message (`ts`, `role`, `text`). The format is the whole contract — write them yourself if you do not run the proxy.
- **Proxy**: appends every exchange after the reply is complete (user line with the `<context_now>` block stripped, then the assistant line). Exact repeats of a recent line are ignored, so clients that re-send history on regeneration do not double every turn. `ANCHOR_TRANSCRIPT=0` turns it off.
- **MCP**: `search_transcript(query, date_from, date_to, limit)` and `record_transcript(role, text)` (for MCP-only setups with no proxy in the path). Both transports.
- **Search**: keyword-and-date only, no model in between. Every term must appear (ASCII case-insensitive, CJK as substrings). Results are spread across days, newest day first, round-robin — one talkative day cannot fill the page and hide an older match. When truncated, the result says how many matches each day had, so narrowing the dates is a one-step move.
- **CLI**: `python anchor_transcript.py --db-path ./anchor_data search "香港 第一次" --from 2026-10-01`; `… days` lists the day files.

## 2. The always-injected layer gets a size readout

Long always-on context gets skimmed, not read. Anthropic's write-up puts the ceiling for the injected layer around 200 lines / 25 KB; our own gateway hit the same wall long before (a 90K system prompt the chat model never looked into).

- `anchor_pinned.injection_size(pinned_dir)` → per-file and total lines/bytes for exactly the files `load_pinned()` joins (tail and the invitation pool excluded), plus `over` against the ceiling.
- `wakeup()` returns `injected_layer_size: {lines, kb, over_limit}`.
- The proxy prints the readout at startup; `python anchor_admin.py <data_dir> injection` prints it any time.
- A readout only. Nothing is trimmed or rewritten; moving detail out of pinned into memories (searchable) is a human decision.

## 3. Dream-time evidence check (`dream_pass(verify=True)`, BYO model, opt-in)

For memories stored in the last `verify_days` (default 7), the pass pulls the transcript lines within ±3 hours of the memory's timestamp and asks the configured LLM one question: is this memory supported by what was said? Verdicts: `supported` / `unsupported` (contradicted, or asserted by no line — an assistant guess recorded as a user fact counts here) / `unclear`.

- Each verdict is written as an annotation on the memory (`[verify 2026-11-09] unsupported: … | <verbatim line>`) and a line in `<db_path>/verify_ledger.jsonl`. **Nothing is rewritten, re-tiered or deleted** — the v1.18 rule stands; the verdict is for the reader and for whoever acts next.
- Memories already carrying a `[verify …]` annotation are skipped; memories with no transcript around them are counted as `no_transcript` and left unannotated so they are checked once transcripts exist.
- Entry points: `dream_pass(verify=True, verify_days=7, llm=…)`, the MCP `dream_pass` tool (`verify`, `verify_days`), `python dream_extras.py --db … --verify --days 7 [--dry-run]`. Without a configured LLM the step reports `skipped` and the rest of the dream pass runs as before.
- Budget: at most 60 memories per run, 6,000 characters of transcript per memory, 300 output tokens.

## Tests

`python tests/smoke_v120.py` — transcript append/dedupe/search/round-robin, proxy logging on/off, size readout (tail excluded, over-limit flagged, nothing trimmed), verifier with a stub LLM (supported/unsupported/no-transcript, annotation + ledger, no text change, no delete, idempotent, dream_pass without an LLM reports skipped). Existing smoke tests unchanged.

## Not in this release

Organised representations (the "wiki" layer) beyond the graph, concept links and pinned files; and the Harvey-style lesson distillation from graded outcomes. For a companion there is no grader — the nearest thing is the person's own corrections, and the lessons belong in the AI's own session state, written by the AI.
