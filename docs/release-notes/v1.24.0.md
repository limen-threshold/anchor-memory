# v1.24.0 — An optional reranker hook (off by default)

[中文说明](v1.24.0_zh.md)

Anchor stays a zero-model library. This release adds one optional seam: if you have a cross-encoder, Anchor will let it re-order the rows it has already chosen. Nothing changes unless you set it.

## The hook

```python
mem.reranker = lambda query, texts: my_model.score([(query, t) for t in texts])   # higher = more relevant
mem.rerank_pool = 30   # default; how many allocated rows the reranker sees
```

- `search()` runs exactly as before (vector lane + keyword lane + slot allocation), but allocates `max(n_results, rerank_pool)` rows, hands their texts to the callable, re-sorts by the returned scores and cuts to `n_results`.
- It only re-orders: no threshold, no filtering, nothing new enters. The review that scoped this release was explicit that a reranker in a store without a downstream judge must sort, not gate — upstream's live traffic put 5× more rows over a replay-calibrated threshold than expected.
- A reranker that raises is logged and ignored; the allocated order is returned. `reranker = None` (the default) is the v1.23 code path, byte for byte.
- Each returned row carries `_debug_rerank` (the callable's score) when the hook ran.

Anchor does not ship a model. The benchmark below used `hs-rerank-1` (a 114M multilingual cross-encoder released by Hindsight in November 2026, run through onnxruntime on CPU); any `(query, text) → score` function works.

## Benchmark

LongMemEval-S, 500 questions, same protocol as v1.20–v1.23 (`benchmarks/longmemeval/`, session-level "all evidence in top-5"). The reranker saw the top-60 allocated rows per question and re-sorted them; it cost about 2 s per question on CPU.

| lane | knowledge-update 78 | multi-session 133 | single-assistant 56 | single-preference 30 | single-user 70 | temporal 133 | **total /500** |
|---|---|---|---|---|---|---|---|
| bare embedder | 76 | 107 | 56 | 27 | 69 | 98 | 433 |
| v1.23 default (this run, live) | 78 | 108 | 56 | 27 | 69 | 98 | 436 |
| **v1.23 default + reranker over top-60** | 77 | 110 | 56 | 28 | 70 | 114 | **455** |

- The live v1.23 number matches the offline replay that chose its keyword base (436 both ways), so the previous release's claim holds on a fresh run.
- The reranker's gain is concentrated where the embedder is weakest: temporal-reasoning questions go from 98 to 114 of 133. Knowledge-update loses one. Every class stays at or above the bare embedder.
- This is the first lane in this benchmark series that is clearly above the bare embedder rather than tied with it (+22 questions; run-to-run noise at this accuracy is about ±8).

Files: `benchmarks/longmemeval/runs_v124/` (summary and per-lane table), `run_retrieval.py --rerank <module.py>` to reproduce with any module exposing `get().score(pairs)`.

## Upgrading

Nothing to do. The hook is `None` unless you set it.
