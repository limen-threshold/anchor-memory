# v1.16.1 — 给没法带请求头的客户端用的秘密路径

[English](v1.16.1.md)

v1.16 HTTP 传输的一个小跟进，起因是接 **grok.com**（connectors → Custom）。

## 改了什么

- `anchor_mcp.py --http --path /mcp-<随机串>`（或环境变量 `ANCHOR_HTTP_PATH`）把 Streamable-HTTP 的端点挪到你自己选的路径上。默认仍是 `/mcp`；已有的配置什么都不用改。
- 路径自定义之后，根页面（`GET /`）不再公布它，并显示 `auth: path`。
- 这种模式下启动横幅显示 `auth=secret path`。
- README：grok.com 和 claude.ai 并列为托管客户端；以及 `--path` 的经验法则。

## 为什么

v1.16 说过「躲在随机隧道网址后面，网址本身就是秘密」。可一旦你照着 README 自己的建议用了**固定的** ngrok 域名，这话就不成立了：`https://<固定域名>.ngrok-free.dev/mcp` 是猜得到的。有些托管客户端只让你贴一个网址，却没有地方填 `Authorization: Bearer …`（至少一部分账号下的 grok.com 自定义连接器；claude.ai 的个人版）。凡是能发请求头的地方，`--token` 仍然是正解；`--path` 是发不了请求头时的退路。

生成一个随机路径：`python3 -c "import secrets;print('/mcp-'+secrets.token_urlsafe(18))"`

## 验证

- `smoke_http.py` 12/12（默认路径，不变）。
- 自定义路径：`GET /` 不显示它，`POST /mcp` → 404，`POST /mcp-<随机串>` → initialize 200，带 `Mcp-Session-Id`。
