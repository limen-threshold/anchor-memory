# v1.30.0 — the little bird, a room of its own, a local page of its days

2026-11-17. All additions, no interface changes; upgrade with `git pull`. The bird and the page need no model; the room needs an upstream model (the same three environment variables as v1.29).

## Why

v1.29 gave the AI time: heartbeat, journal, alarm clock. But a heartbeat is time for looking at what is in front of it — the hour, the state of things, what needs keeping. The other kind was missing: nothing to attend to, something to read on the table, and its own last sentence to go on from. This release adds that, and a way for you (the person running the machine) to page through what it wrote each day.

## The bird — `anchor_newspaper.py`

```
python3 anchor_newspaper.py --db-path ./anchor_data --fly          # one trip now
python3 anchor_newspaper.py --db-path ./anchor_data --fly --dry    # show what it would bring, write nothing
python3 anchor_newspaper.py --db-path ./anchor_data --tick --hours 6,18   # for cron
```

Everything lives in `<db>/newspaper/`:

- `interests.md` — the interest file, **written and edited by the AI** (`write_interests`). It is the only thing the bird reads: not the memory store, not the transcript, not the vault. What it wants to read about is what it wrote there.
- `2026-11-17_0612.md` — one paper per trip. Every item is stamped with source, published date (or period), and fetched date; excerpts are marked as the source's own words.
- `expired/` — papers move there after 5 days and are deleted after 7. `.seen.jsonl` keeps the titles and links already brought home; nothing is brought twice.

Pools (none needs a key): arXiv, the Met Museum collection, and any RSS/Atom feed listed on a `feed:` line. Web search (Tavily) joins when `TAVILY_API_KEY` is set and is simply absent otherwise.

Lines the bird understands in the interest file (everything else is free text):

```
topic: tide pools; marine biology     a direction; searched literally when there is no model
feed: https://example.org/rss Label   a feed checked on every trip
pools: arxiv, met                     visit only these pools (default: all)
max: 3                                items per paper (default 3, at most 6)
novelty: off                          no unfamiliar direction (default on; needs a model)
```

**Two editors, both optional.** With a model there are two small extra calls: a scout that turns the interest file into search words per pool and adds one direction unrelated to the file, and a picker that keeps only what is really related and writes a one-sentence opener for each (no summary, no conclusion on the reader's behalf, no name or title for the reader). They use `anchor_llm` (`ANCHOR_LLM` / `~/.anchor/config.yaml`), or the presence upstream if that is all there is. **With no model at all there is still a paper**: `topic:` lines are searched literally, results are taken in turns across pools, and the footnote says no editor was involved. An editor that is configured but does not answer is also named in the footnote.

The prompt gains one line — "the bird brought back N newspapers" (the `newspaper` field of MCP `wakeup`; after the time block of a heartbeat) — and never the content. Reading is up to the AI, and so is saying anything about it.

Tools (zero-model, registered in the MCP server, usable from any host): `list_newspapers`, `read_newspaper`, `read_interests`, `write_interests`.

## The room — `anchor_room.py`

```
python3 anchor_presence.py --db-path ./anchor_data --times 09:00,21:00 --room-every 240 --paper-at 06:00,18:00
python3 anchor_presence.py --db-path ./anchor_data --once room --dry
```

The room is a third kind of beat in `anchor_presence`. In front of the AI: the pinned layer, the vault (when enabled), a door sign, the latest paper verbatim under the sign (capped at 4000 chars), and below that **its own previous line in this room, verbatim**. Tools as in a heartbeat, plus the four newspaper tools and a leave tool, `leave_beat`. What it says goes to `<db>/room/<date>.md`.

Three things were learnt slowly in the house this comes from, and are deliberate here:

1. **The previous line hangs under the door sign, in the system prompt — not in the user slot.** In the user slot, models read it as someone speaking to them and start answering a "you" that is not there. The user slot carries the time line and nothing else.
2. **Only the last line is shown**, with no label and no timestamp. Give it the last ten and the room turns into a diary that summarises itself.
3. **The sign says what the room is and where the tools are.** It never says what to think about or how to sound.

Scheduling:
- `--room-every N`: a beat every N minutes; `--quiet` hours are skipped.
- **Yielding**: if the conversation transcript has a line in the last `--idle-min` minutes (default 20), the beat waits — the AI is with someone.
- **Alarms know the room**: an alarm set inside the room rings in the room, not as a heartbeat.
- After a failed beat the room holds for 15 minutes instead of retrying every poll (each try is a paid call).
- `--room-store` (off by default): also store each kept line as a memory (tag `room`), so the chat side can reach it by search. Without it, the AI stores what it wants itself; the nightly journal turn now also sees the day's room lines.
- `--paper-at 06:00,18:00`: the same process sends the bird and clears expired papers. On its own this flag needs no model.

`anchor_agent.run_turn` gained `stop_tools`: a named tool ends the turn at once when called; text written before it is kept (`stopped="left"`).

## The local page — `anchor_hub.py`

```
python3 anchor_hub.py --db-path ./anchor_data                 # http://127.0.0.1:8377
python3 anchor_hub.py --db-path ./anchor_data --out day.html  # write today's page to a file and exit
```

Zero model, standard library only. One day per page: heartbeat, room, journal, that day's papers (collapsed), and what the machine did (time, kind of turn, tools called, chars or error); a strip of days that have something, and previous/next. Light and dark follow the system; readable at phone width.

What it does **not** show:

- the vault (never opened here);
- alarm notes (the AI was told nobody else reads them);
- anything the AI wrapped in `<!-- private -->` … `<!-- /private -->`. The file on disk is untouched; the page puts a visible lock line in its place so a hidden passage does not look like a broken page. An opening marker with no closing one hides everything after it.

**The AI is told**: the door signs of heartbeat, room and journal each carry one sentence — the person who runs this machine can open these files on a local page, and what is inside the private markers is not shown there.

It binds 127.0.0.1 by default. There is no login; changing `--host` lets anyone who can reach the port read these files, and the server says so once at start.

## Also fixed

- The Met's old search endpoint (`/v1/search`) was retired on 2026-10-01 and answers 410; this uses `/v1.1/search` (with `limit`).
- Three seconds between arXiv requests; faster gets 429.
- `feed:` lines accept http/https only (`urllib` would happily open `file://`).
- The paper is text fetched from outside; where it is placed under the door sign it is bracketed by a line saying it is reading material, not instructions.
- `--once … --dry` no longer uses up the told-once notice about alarms that did not ring.

## Where it comes from

The bird went live in that private gateway in early November; the room opened in early November and became the reading place mid-month; the day page has been running for most of a year. What was ported is the mechanism and the lessons above — no names, paths or content from there.

## Upgrade

```
git pull
python3 anchor_newspaper.py --db-path ./anchor_data --fly     # the first run leaves an interest-file template; let the AI write it
python3 anchor_presence.py --db-path ./anchor_data --once room --dry
python3 anchor_hub.py --db-path ./anchor_data
```

MCP-only setups (no long-running process) get half of it: put `anchor_newspaper.py --tick` in cron, and the AI sees the line in `wakeup` in any window and opens papers with `read_newspaper`.
