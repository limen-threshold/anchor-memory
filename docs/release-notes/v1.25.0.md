# v1.25.0 — Four silent failures from an outside review

2026-11-14. No interface changes; upgrading is `git pull` + `pip install -r requirements.txt`.

## Where this came from

A reviewer with no prior knowledge of the repository (a clean-context Claude, read-only clone, no model calls, no database access) read the code top to bottom. What it found had one thing in common: **nothing raised**. Features appeared to run while quietly producing the wrong result. This release fixes the top of its list.

## What changed

### 1. Two clock bases: `dream_pass(verify=True)` was eight hours off for UTC+8 users
Memory timestamps are UTC (`anchor_db` uses `utcnow()`); transcripts and the timeline are local wall-clock time (`datetime.now()`). The dream pass took a memory's UTC stamp ±3 hours and cut the local-time transcript with it. For a UTC+8 user the window was eight hours off — either no transcript at all (`no_transcript`) or the wrong conversation "verified".

Fix: `anchor_guards.py` adds `parse_ts_naive` / `utc_to_local_naive`; `_transcript_around` converts the memory stamp to local time before opening the window, and `verify_recent`'s "last 7 days" compares against `utcnow()`. Storage format is unchanged (naive UTC).

### 2. A timezone-aware timestamp took the whole `search()` down
In `_recency_boost` the `fromisoformat` sat inside a `try`, the subtraction outside it. One imported row stamped `2026-11-14T18:00:00+08:00` in the candidate set and the whole search returned `{"error": "can't subtract offset-naive and offset-aware datetimes"}`.

Fix: every timestamp goes through `parse_ts_naive` (naive UTC) before arithmetic; `store(timestamp=…)` normalises on the way in, accepting both `Z` and `+08:00`.

### 3. Library `print` calls wrote into the stdio JSON-RPC channel
Over stdio the MCP protocol is stdout — and so were the diagnostics in `anchor_memory` / `anchor_db` / `concept_link`. An ordinary `store_memory` that triggered the near-duplicate merge sent the client a non-JSON line. A single malformed input line also raised out of the read loop and ended the server.

Fix: library diagnostics go to stderr; a malformed line gets a JSON-RPC `-32700` parse error and the server keeps reading. CLI scripts still print to stdout.

### 4. The keyword lane truncated before it scored
`keyword_search` was `WHERE … LIKE … LIMIT 300` with no `ORDER BY`: the first 300 rows in rowid order, scored by matched-token count afterwards in Python. With more than 300 rows containing one common token, the row matching every token could be absent from the pool entirely (the reviewer reproduced it with 350 "garden" rows and one "garden hose"). Bigger store, commoner word, worse odds.

Fix: `ORDER BY` matched-token count in SQL, then `LIMIT`. No timestamp tie-break (the v1.10 lesson: the lane must not pre-decide recency).

### 5. `search_multi` still capped by bare day
v1.21 changed the per-query same-day cap to a (day, conversation entity) key, but the re-cap on the merged multi-intent list still counted bare days — and the proxy's real turns go through `search_multi`. Both places now use the same key, and keyword-lane hits keep their own ledger as in `search()`.

### 6. The README's recommended `gpt-5-nano` rejected the parameters the code sent
`anchor_llm` sent `max_tokens` + `temperature=0.5` to every OpenAI model; the gpt-5 and o-series require `max_completion_tokens` and accept no non-default temperature. Configured as the README suggested, every curator and intent-split call returned HTTP 400, which the caller's broad `except` swallowed — "model configured, nothing stored".

Fix: `openai_token_kwargs(model, …)` picks parameters by model family (reasoning models get `max_completion_tokens` with headroom for hidden reasoning).

### 7. Near-identical but naming a different thing = an update, not a duplicate
The near-dup gate (cos ≥ 0.93) only let through texts containing a correction word (勘误 / 更正 / 作废 / correction). "The cat is Scott" → "The cat is Scout" was swallowed, and the **wrong** entry gained a citation. Now, when either text carries a Latin word or number the other lacks, both rows stay (the dream pass's fact-check sees the pair); pure rephrasings still merge. CJK names are not covered by this rule (there is no general CJK entity list) and stay with the similarity gate.

### 8. The dream pass no longer cites random memories
Auto-discovery sampled 5 memories nightly and searched 3 neighbours each without `no_cite=True`, so 15 random memories gained `usage_count+1` every night and drifted to the top over months. Fixed.

### 9. Install traps
- `requirements.txt` gains `pyyaml` (required by `anchor_llm` to read `config.yaml`; missing, the config was silently read as empty → "No LLM configured") and `httpx` (required by the proxy). A present `config.yaml` with no pyyaml is now an explicit error.
- README states that first start downloads the ~470 MB embedding model from huggingface.co, how to warm it up, and how to set `HF_ENDPOINT` for a mirror; and that the model embeds only the first 128 tokens.
- Every text-file read/write (identity files, timeline, concept cache …) passes `encoding="utf-8"` (Windows defaults to GBK; writing `我是谁.md` with an emoji raised).
- SQLite runs in WAL mode with a 5 s `busy_timeout` (proxy and MCP open at once no longer hit "database is locked"); `memories` gains `timestamp`, `(tier, timestamp)` and `pinned` indexes.
- `recent_timeline.md` appends are locked and atomically replaced; the proxy's background thread and the MCP server no longer lose lines to each other.
- README's edge-decay description now matches the code (every edge ×0.9; edges ≥1.5 a further ×0.95); the release-notes index lists v1.20–v1.25.

## Not changed

- Stored timestamps remain naive UTC. Making them timezone-aware would touch every existing row for little gain; converting at the boundaries is enough.
- CJK name differences are not a separate near-dup rule. Add words to `near_dup_bypass_words` if you need one.
- The review also listed proxy issues (image parts dropped from the last user message, LLM calls running synchronously on the event loop, malformed curator JSON dropping the whole turn with no dead-letter) — next release.

## Upgrading

```
git pull
pip install -r requirements.txt
```

Opening an existing store with this version creates the three indexes and switches the journal to WAL (two new files, `memories.db-wal` / `-shm` — include them in backups, or run `sqlite3 memories.db "PRAGMA wal_checkpoint(TRUNCATE)"` first). Nothing else migrates.
