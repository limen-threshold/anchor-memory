# v1.14 — Recall slot gates, store-side dedup, calendar reads

[中文](v1.14_zh.md)

Six mechanisms ported from the production system this repo mirrors. All six ran there for weeks to months before landing here; all six are zero-LLM. Port, not copy — each is re-expressed in Anchor's own API.

## 1. Slot allocation gates on `search()` / `search_multi()`

The recurring failure: five memories stored the same afternoon about one event fill every result slot, and the second-most-relevant *topic* never surfaces. Measured case: "memories of Hong Kong", 8 slots, all 8 taken by one 1999 layover stored as 4 entries in one day; the actual 2026 trip, zero.

Three gates on the instance, all about *who gets a slot*, none about scores:

| knob | default | meaning |
|---|---|---|
| `same_day_cap` | 2 | at most N results from one calendar day (UTC); `0` disables all three gates |
| `older_days` / `older_reserve` | 7 / 2 | keep ≥2 memories older than 7 days when the pool has them ("the first time" survives next to "the latest time") |
| `recent_days` / `recent_reserve` | 3 / 1 | keep ≥1 memory ≤3 days old when the pool has one (a fresh event is not drowned by an old cluster) |

Blocked entries stay in the pool for the floors. Keyword-lane hits keep a separate day ledger so a literal match can't crowd out the vector lane's quota. `search_multi` re-applies the cap once more on the merged list (k queries could otherwise bring k × cap from one day).

## 2. `exclude_tags` on `search()` / `search_multi()` / MCP

Tags dropped **before** slots are counted. The bug this fixes: excluding after ranking lets an excluded tag eat a slot it then vacates — a genuine `core` hit at rank 4 of 4 was pushed out by three transcript entries that were then discarded.

## 3. Store-side near-duplicate gate

`store()` now checks the nearest existing memory first. Cosine ≥ `near_dup_merge_sim` (default **0.93**, calibrated for the default MiniLM embedder — re-calibrate if you swap models; a Qwen3 embedder needed ~0.96 for the same percentile) → the new text is **not** stored; the existing one is cited (`usage_count+1`), a `near_dup_merge` event is logged, and `store()` returns the **survivor's id**. The MCP `store_memory` tool reports `status: merged_into_existing` so the model gets an honest receipt.

Two deliberate holes:
- Re-storing the **same id** is an edit, not a duplicate — goes straight to the upsert.
- Text containing any of `near_dup_bypass_words` (default `勘误 / 更正 / 作废 / correction`) is always stored. A correction is near-identical to the entry it corrects *by construction*; without the bypass the gate swallows the correction and the wrong entry survives. This was observed in production before the bypass existed.

Set `near_dup_merge_sim = 0` to disable.

## 4. `read_memories_by_date` (MCP) / `AnchorMemory.read_by_date()`

The calendar path. Semantic search answers "what do I know about X"; this answers "what happened on the 6th", which similarity ranking is bad at and which you shouldn't have to gamble on when you already know the date. `parse_date_range()` understands ISO, Chinese (`3月6日` / `三月六日` / `昨天` / `上周` / `上个月` / `3月`), English (`March 6` / `yesterday` / `last week`), and `最近` / `recently` (last three days). Boundaries are computed on the **local** calendar and shifted to UTC to match stored timestamps — an evening query in UTC−7 would otherwise put "today" on tomorrow's UTC date. Paginated, 20 per page.

## 5. Keyword lane: single CJK characters no longer match; jieba is required

`_tokenize_query` previously kept lone Chinese characters. A lone character LIKE-matches every compound containing it — `草` hits 草莓 / 草稿 / 草原 — so "你给了他草" returned ten keyword hits, none about grass. Every token now needs ≥2 chars. The one exemption is `db.keyword_single_char_allow`, a set for single-character proper names that genuinely mean one thing in your data.

`jieba` moves from "optional" to required in `requirements.txt`. Without it CJK text has no word boundaries and the keyword lane is effectively dead for Chinese memories; it is harmless for English-only data.

## 6. `anchor_proxy`: streaming side effects run in `finally`

If the client closed the tab mid-stream, the generator was cancelled and the post-loop `side_effects()` call never ran — the tail (`last_session.md`) and the curator silently missed the turn, which is exactly the crash the proxy exists to survive. Side effects now run in `finally`; a partial reply is still a turn.

## Compatibility

- `search()` default behaviour changes (gates on). Set `same_day_cap = 0` on the instance for the v1.13 top-N.
- `store()` may now return an id other than the one you passed. Check the return value if you keep your own index.
- New MCP tool `read_memories_by_date`; new `exclude_tags` argument on `search_memory` / `search_multi`; `store_memory` may return `status: merged_into_existing`.
- serverInfo version → 1.14.
