# v1.17.1 / v1.18.1 — identity files actually reach the window

[中文](v1.17.1_zh.md)

**Reported by 大管家**, who connected Anchor to claude.ai, upgraded to v1.17.0, wrote an identity file with the new tool — and ran a control group before writing to us:

| put in the pinned dir | came back from `wakeup()`? |
|---|---|
| `session_state.md` (control) | ✅ |
| an identity file with a name of their own | ❌ |

The control passed, so it was not their environment. They then pointed at the exact lines: the `wakeup` branch of `anchor_mcp.py` read three hard-coded filenames, and `load_pinned()` — the function that loads the rest of the pinned dir — was only ever called from `anchor_proxy.py`. We run the proxy, so we never saw it. **v1.17.0 built the writing half of identity files and not the reading half**: in an MCP-only setup `write_identity_file` wrote, `list_identity_files` listed, and the file never reached a window.

Same fix, two tags: **v1.17.1** is v1.17.0 plus this fix and nothing else. **v1.18.1** is the current line — this fix on top of [v1.18.0](https://github.com/limen-threshold/anchor-memory/blob/main/docs/release-notes/v1.18.0.md), which you want anyway if an LLM is configured and you run `dream_pass`. If in doubt, take v1.18.1.

## Fixed

- **`wakeup()` returns identity files.** New key `identity`: `[{"name", "content"}, …]`, verbatim, in `_order.txt` order (or by filename when there is no manifest), placed first — who you are, before what you were doing. Files that already have their own key (`session_state`, `recent_timeline`, `last_session`) are not repeated.
- **`--wakeup-text` had the same three hard-coded names.** Both paths now go through one function (`_attach_pinned_layer`), so they cannot drift apart again. The text output prints each identity file under `## Identity file: <name>`, before session state.
- **The wording is now true.** "Every `.md` that `wakeup()` would load", "`wakeup()` returns verbatim every window", and the `_order.txt` warning ("wakeup will not load it until the manifest is updated") all described behaviour that did not exist outside proxy mode. We did not soften the sentences; we made the code do what they say, manifest included. The v1.17.0 notes carry an erratum. The `wakeup` tool description now mentions `identity`.
- **Found while in there — the invitation pool was being injected whole.** `invitations.md` lives in the pinned dir, so with no `_order.txt` the proxy's `load_pinned()` put the entire card pool into the system prompt on every turn, which defeats "one card a day". It is now always excluded from the pinned layer and from `identity`; `list_identity_files` reports it as `kind: invitation_pool`, `loaded_by_wakeup: false`; `write_identity_file` refuses the name (use `invitation_add`).

## If you used the workaround

大管家's interim fix — store the whole letter as one memory, `tier=core`, `pin_memory` — is sound and stays sound: pinned memories come back from `wakeup()` verbatim. After upgrading you can keep it, or move the text into an identity file; with both in place the model simply reads it twice. The difference is what it is, not how it arrives: a pinned memory is a fragment you promoted; an identity file is a whole text you maintain and version (`identity_archive/`).
