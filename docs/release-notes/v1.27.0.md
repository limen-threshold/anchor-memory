# v1.27.0 — Four mechanisms ported from the house gateway

2026-11-16. No interface changes; upgrade is `git pull`.

Anchor is the memory layer lifted out of a private gateway, where every "how memories are stored and found" change runs for weeks before it is ported here. This release ports the four that soaked between September and November and pass the three house rules for this repo: usable on any platform, runs with zero models, carries none of the house's own name lists.

## 1. Proxy: the host's own side requests pass through

Front-ends like Open WebUI send *extra* requests through the **same** `/chat/completions` endpoint: title generation, tag generation, follow-up suggestions. Each wraps the whole conversation in a `### Task:` prompt. Nobody is talking. The proxy used to treat each as a turn: inject a `<context_now>` block, run recall, run the curator — so the store gained memories about "generate 3 tags", the transcript filled with templates, and every turn cost two or three extra model calls.

`is_host_task()` now checks the last user message or the system prompt against those templates (`### Task:`, `Generate 1-3 broad tags`, `Create a concise, 3-5 word title`, `Suggest 3-5 relevant follow-up questions`, …). A match is forwarded untouched: no injection, no recall, no transcript line, no curator pass.

## 2. Keyword lane: CJK words with a suffix also try their root

jieba keeps 「姥姥家」 ("grandma's place") as one token, so a memory that only says 「姥姥掌勺」 ("grandma cooked") never surfaced in the keyword lane. A small fixed set of locative / plural suffixes (家里, 那边, 那儿, 这边, 家, 们, 里, 那, 边) is stripped and the root joins the **same concept group** as the surface word: a row matching either counts once, the denominator is the number of groups, so the expansion cannot dilute the match score. Roots are at least two characters; zero model, zero wordlist; a wrong strip costs one extra LIKE candidate. `keyword_groups(query)` exposes the grouping.

## 3. Curator: unknown people get a bare name, never an invented relationship

On 2026-11-14 the house caught its curator filing someone who had only been named as "a friend". The curator prompt now says: if this exchange does not state who the person is to the user, store the name only — do not guess friend / colleague. Affects the BYO-LLM proxy curator only; MCP-only users are untouched.

## 4. Store: opt-in same-scene merge

A curator that re-reads a conversation still in progress stores the same scene several times at similarities just under the global gate (0.93). When you `store(entity=<session id>)` and a neighbour has the same `entity` and was stored within `scene_merge_window_sec` (default 2 h), the merge threshold becomes `scene_merge_sim` instead. **Default `None` = off**: the house value was calibrated on a different embedder and is not copied; measure your own, e.g. `mem.scene_merge_sim = 0.85`.

## Deliberately not ported

- Rare-literal boost: the house enables it for explicit queries only; the automatic recall path keeps it off, so it has not earned a default.
- Entity rosters, the recall judge, the near-miss ledger, the transitional bridge: they need the house's name lists, a local model, or more soak time.

## Upgrading

```
git pull
```

No migration. Root variants and host pass-through are on automatically; same-scene merge is yours to switch on.
