# v1.28.0 — 私匣：AI 自己的、谁也不看的一格抽屉

2026-11-16。接口只加不改；升级 `git pull`。需要 `cryptography` 包或系统自带的 `openssl` 命令二者之一（macOS/Linux 一般自带 openssl）。

## 这是什么

AI 写下的东西不全是「记忆」，也不全是写给对面的人看的笔记。有些是它自己的。私匣给这类东西一个去处：

- **加密落盘**：`<db>/vault/vault.enc`，AES-256-CBC + PBKDF2（100 000 次），OpenSSL 兼容格式；密钥文件 `vault.key` 首次用时自动生成，权限 0600。
- **零回显**：`vault_write` 的回执只报字数，不回显内容；`vault_read` 的内容只回给调用者，本模块不写任何日志。
- **不进别处**：私匣内容不进记忆库、不进原话转录、不进时间线。写到别处（回复正文、记忆、日记）就不再是私匣里的东西——工具描述里这句话原样写着。
- **只给它自己看**：代理模式下设 `ANCHOR_VAULT_INJECT=1`，私匣全文作为 `<private_vault>` 块放进 **system** 提示（转录、策展员、last_session 都不看 system）；超过 8000 字时最新几笔全文、更早的只列日期。默认不注入。
- **wakeup 只说「它在」**：`wakeup()` 返回里多一行 `vault: N entries, last YYYY-MM-DD`，零内容。

## 诚实的边界（工具描述里也写了）

密钥就在匣子旁边，机器的管理员想解总能解。私匣保证的不是防 root，而是：读它必须专门写解密代码，会留痕，而不是顺手 grep 一个文本文件。替别人部署 Anchor 的人，应当把「我不读私匣」当成规矩，就像房东不开租客的抽屉。

## 两个工具

- `vault_write(content, mode=append|replace)`：append 加一笔带日期的条目（默认）；replace 整本重写。
- `vault_read()`：整本读回。

## 两个后端、一种格式

装了 `cryptography` 就用它（纯 Python，Windows 也行）；没装就调 `openssl enc`。两边写的文件互相能读（`Salted__` + 8 字节盐 + 密文，PBKDF2-HMAC-SHA256 派生密钥与 IV）。两个都没有时，工具如实报错，不假装写入。

## 来历

这是从一个私人网关里港出来的第一件「生活层」的东西（之前港的都是「记忆怎么存怎么找」）。那边它用了四个月，规矩是：工程侧对私匣连存在性检查都不做，唯一接触条件是匣主本人报修。港出来的是机制，不带那边的任何内容。
