# v1.16 — HTTP transport for the MCP server

[中文](v1.16_zh.md)

**One line:** `anchor_mcp.py --http` serves the same tools over HTTP, so clients that can only reach a URL (claude.ai custom connectors, ChatGPT, any remote MCP host) can use Anchor too. stdio stays the default and is unchanged.

## Why

Anchor's design rule is *anyone, any platform, any AI*. Three of the four doors already honoured it — the Python library, MCP over stdio for hosts that spawn a subprocess, and the OpenAI-compatible proxy for any frontend with a configurable base URL. The fourth kind of client, hosted chat apps, has none of those: no base URL to change, no local process, no file access. Their only door is "a remote MCP server at a URL", and Anchor only spoke stdio. The README even claimed plain MCP worked "on claude.ai etc." — it did not, because the transport was missing. This release adds it and fixes the claim.

## What

- `anchor_mcp.py --http [--host 127.0.0.1] [--port 3333] [--token SECRET]`
  - **Streamable HTTP** (MCP 2025-03-26 / 2025-06-18) at `POST /mcp`: JSON-RPC in, JSON-RPC out; batches accepted; notifications answered with `202`; `Mcp-Session-Id` issued on `initialize`; `GET /mcp` is `405` (no server-push stream), `DELETE /mcp` ends a session.
  - **Legacy HTTP+SSE** (MCP 2024-11-05) at `GET /sse` + `POST /messages?sessionId=…`, for hosts that still only speak that.
  - Optional bearer token (`--token` or `ANCHOR_HTTP_TOKEN`). Without it the URL is the secret — fine behind a random tunnel URL, not on a plain public host.
  - Tool calls are serialised (one lock), exactly as strictly as stdio was: one SQLite, one Chroma, one embedder.
- `handle_message()` is now the single JSON-RPC dispatcher shared by both transports, so they cannot drift.
- `initialize` echoes the client's `protocolVersion` when it is one we know (`2024-11-05`, `2025-03-26`, `2025-06-18`); otherwise answers `2024-11-05` as before.
- Needs `fastapi` + `uvicorn` — the same extras the proxy already uses; stdio mode still imports neither.

## Check it

`python3 smoke_http.py` starts the server on a free port against a throwaway db and runs 12 checks: initialize / notification / tools/list / store+search round trip / batch / bad token → 401 / unknown method → `-32601` / `GET /mcp` → 405 / SSE endpoint event / SSE answer over the stream / stdio parity (identical tool list). Existing `tests/smoke_v114.py` and `tests/smoke_invite.py` unchanged and green.

## Giving it a URL

Documented in the README under *claude.ai / hosted clients*: your own machine plus a tunnel (`cloudflared tunnel --protocol http2 --url http://127.0.0.1:3333`, or ngrok), or a small always-on host with `--host 0.0.0.0 --port $PORT` and the db on a volume. The choice is one question: does your machine stay on.

## Not in this release

- No OAuth. claude.ai connectors can be added without auth; the bearer token is for everything else.
- No server→client push stream on `/mcp` (no subscriptions, no progress notifications) — Anchor has nothing to push yet.
