# v1.14 — 召回名额闸、存入时去重、按日历读

[English](v1.14.md)

从这个仓库所镜像的生产系统移植过来的六个机制。六个都在那边跑了几周到几个月才落到这里；六个都不需要模型。是移植不是照抄——每一个都用 Anchor 自己的 API 重新表达。

## 1. `search()` / `search_multi()` 的名额分配闸

反复出现的故障：同一个下午为同一件事存的五条记忆，把结果的每个名额都占满，第二相关的那个*话题*永远浮不上来。实测案例：搜「香港的记忆」，8 个名额，全被一次 1999 年转机占掉（同一天存了 4 条）；真正的 2026 年那趟旅行，零条。

实例上的三道闸，管的都是*谁能拿到名额*，不碰打分：

| 旋钮 | 默认 | 含义 |
|---|---|---|
| `same_day_cap` | 2 | 同一个日历日（UTC）最多 N 条；设 `0` 关掉全部三道闸 |
| `older_days` / `older_reserve` | 7 / 2 | 候选里有的话，至少保留 2 条 7 天以前的记忆（「第一次」能和「最近一次」并排活下来） |
| `recent_days` / `recent_reserve` | 3 / 1 | 候选里有的话，至少保留 1 条 3 天以内的记忆（新发生的事不被一簇旧记忆淹掉） |

被挡下的条目仍留在候选池里，供两条保底捡回。关键词车道的命中单独记一本同天账，所以一个字面匹配挤不掉向量车道的名额。`search_multi` 在合并后的列表上再过一次同天上限（否则 k 个查询可以从同一天带回 k × 上限条）。

## 2. `search()` / `search_multi()` / MCP 的 `exclude_tags`

标签在**数名额之前**就被排除。它修的 bug：先排名再排除，会让被排除的标签先吃掉一个名额、再把它空出来——一条真正命中的 `core` 记忆排在 4 个名额的第 4 位，被三条随后被丢弃的聊天转录挤了出去。

## 3. 存入时的近重复闸

`store()` 现在会先查最近的那条已有记忆。余弦相似度 ≥ `near_dup_merge_sim`（默认 **0.93**，是按默认的 MiniLM 嵌入模型标定的——换模型要重新标定；同样的分位在 Qwen3 嵌入上大约要 0.96）→ 新文本**不存**；已有的那条被引用一次（`usage_count+1`），记一条 `near_dup_merge` 事件，`store()` 返回**幸存那条的 id**。MCP 的 `store_memory` 工具会回 `status: merged_into_existing`，让模型拿到一张诚实的回执。

两个故意留的口子：
- 重存**同一个 id** 是编辑，不是重复——直接走更新。
- 文本里含有 `near_dup_bypass_words` 里任何一个词（默认 `勘误 / 更正 / 作废 / correction`）的，一律照存。更正条*天然*就和它要更正的那条几乎一模一样；没有这个口子，闸会把更正吞掉、让错的那条活下来。这个口子加上之前，生产环境里真的发生过。

设 `near_dup_merge_sim = 0` 关闭。

## 4. `read_memories_by_date`（MCP）/ `AnchorMemory.read_by_date()`

翻日历的路。语义搜索回答的是「关于 X 我知道什么」；这条路回答的是「6 号那天发生了什么」——相似度排序不擅长这个，而你既然已经知道日期，就不该去赌。`parse_date_range()` 认得 ISO 格式、中文（`3月6日` / `三月六日` / `昨天` / `上周` / `上个月` / `3月`）、英文（`March 6` / `yesterday` / `last week`），以及 `最近` / `recently`（最近三天）。边界按**本地**日历计算、再换算成 UTC 去对存储的时间戳——否则在 UTC−7 的晚上查「今天」，会落到 UTC 的明天。分页，每页 20 条。

## 5. 关键词车道：单个汉字不再参与匹配；jieba 变为必装

`_tokenize_query` 以前会保留单个汉字。单个字做 LIKE 匹配，会命中所有含它的词——`草` 命中 草莓 / 草稿 / 草原——于是「你给了他草」返回十条关键词命中，没有一条跟草有关。现在每个词至少要 2 个字。唯一的豁免是 `db.keyword_single_char_allow`：一个集合，放那些在你的数据里确实只指一样东西的单字专名。

`jieba` 在 `requirements.txt` 里从「可选」变成必装。没有它，中文文本没有词边界，关键词车道对中文记忆等于是死的；对纯英文数据无害。

## 6. `anchor_proxy`：流式回复的收尾动作放进 `finally`

如果客户端在流到一半时关了标签页，生成器被取消，循环后面的 `side_effects()` 就永远不会跑——尾巴（`last_session.md`）和 curator 都悄悄漏掉这一轮，而这恰恰是代理存在的意义要扛住的那种崩溃。收尾动作现在在 `finally` 里跑；说到一半的回复也是一轮。

## 兼容性

- `search()` 的默认行为变了（闸默认开）。想要 v1.13 的纯 top-N，在实例上设 `same_day_cap = 0`。
- `store()` 现在可能返回一个不同于你传入的 id。如果你自己维护索引，请检查返回值。
- 新 MCP 工具 `read_memories_by_date`；`search_memory` / `search_multi` 新增 `exclude_tags` 参数；`store_memory` 可能返回 `status: merged_into_existing`。
- serverInfo 版本 → 1.14。
